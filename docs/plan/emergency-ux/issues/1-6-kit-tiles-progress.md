# 비상 가방 아이콘 타일과 진행 막대

기준 코드: `023aa29`(`main`, 2026-11-18)

## 배경

- **사용자 평가:** "글과 체크박스 구조는 사용자에게 친화적이지 않다."
- **바꾸는 것:** 체크박스 글 목록(`KitChecklist`)을 아이콘 타일로 바꾼다. 타일을 누르면 담기고, 목록마다 진행 막대("3/7 챙김")가 있다.
- **그대로 두는 것:**
  - 저장 키 `war-risk:kit:v1`, 값 형식(담은 id의 JSON 배열), 항목 id·문장·순서
  - 그래서 개편 전에 체크한 항목이 새 타일에서 담긴 상태로 보인다.
- **담은 타일 표시(plan.md Q9 결정):** 강조한다(채운 바탕 + 체크 아이콘). 지금처럼 흐리게 하지 않는다. `contrast.spec.ts`의 "체크한 항목이 더 흐리다" 위계 검사는 가방 상태에서 뺀다(명세 변경).
- **공용 상태:** 첫 화면 가방 카드(1-9)가 같은 담기 상태를 쓴다. 같은 탭의 두 컴포넌트가 함께 바뀌고 하이드레이션이 어긋나지 않게, 브라우저 저장소를 구독하는 훅으로 둔다(예: `useSyncExternalStore`, 서버 값은 빈 배열).

## 범위

- **포함:**
  - `KitChecklist`를 타일 화면으로 교체(이름은 구현에서 정함)
  - 항목 아이콘 대응표 15개(`GO_BAG_ITEMS`·`STOCK_ITEMS` id → 그림, 1-1 틀 사용)
  - 목록별 진행 글자·진행 막대
  - 공용 담기 상태 훅(1-9가 쓴다)
  - 출처: 항목이 가리키는 출처만 영역 끝에
  - `e2e/emergency-kit.spec.ts`의 가방 부분 교체, `e2e/contrast.spec.ts` 가방 상태 교체
- **제외:**
  - 항목 문장·id 변경, 항목 추가·삭제
  - 계산기(1-7, 1-8)
  - 첫 화면 카드(1-9)

## 화면 (plan.md 7-3, 7-7)

- 영역: `section#kit`, h2 "비상 가방", 안내 "담은 항목은 이 브라우저에만 저장됩니다."
- 목록 제목(h3)은 지금 그대로: "들고 나가는 3일 가방(1인 1개)", "집에 두는 7일 비축"
- 제목 옆 진행 글자 "{담은 수}/{전체} 챙김"과 진행 막대(`progress` 또는 `role="progressbar"`, 접근 이름 예 "들고 나가는 3일 가방 챙긴 항목")
- 타일: `button[aria-pressed]`, 안에 아이콘(aria-hidden)과 항목 문장. 담으면 바탕을 채우고 체크 아이콘을 보인다.
- 열 수: 360 2열, 768 3열, 1080·1440 4열. 두 목록은 위아래.
