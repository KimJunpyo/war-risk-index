# 전쟁 가능성 지수 보조 글자 명도 대비 기획안

작성일: 2026-11-11 · 상태: 확정 · 열린 질문 Q1~Q4 사용자 결정 반영(2026-11-11) · 이전 기획: `docs/plan/ui-polish/` (M5~M7 완료) · GitHub 마일스톤: "M8. 보조 글자 명도 대비"

## 1. 목표

어두운 화면의 작은 보조 글자(10~12px)와 링크 밑줄이 WCAG 2.2 AA 기준을 넘게 한다. 글자 크기·배치·문구는 그대로 두고 색만 바꾼다.

1. 보조 글자(`text-neutral-500`·`-600`, SVG `fill-neutral-500`, 지도 나라 이름 `#6b7280`)의 명도 대비(contrast ratio)를 4.5:1 이상으로 올린다(WCAG 1.4.3 Contrast (Minimum)).
2. 링크 밑줄(`decoration-neutral-700`)과 배경의 대비를 3:1 이상으로 올린다(WCAG 1.4.11 Non-text Contrast).
3. 주 글자 > 보조 글자 > 링크 밑줄 순서의 시각 위계(visual hierarchy)를 유지한다.
4. 화면에 보이는 글자 전체의 대비를 e2e로 실측해, 기준에 못 미치는 색이 다시 들어오지 않게 막는다.

## 2. 대상 사용자

- 일반인. 휴대폰(360px)으로 뉴스를 보다 들어오는 사람과 PC(1440px)로 자세히 보는 사람(ui-polish와 같음).
- 특히 어두운 배경 위 작은 회색 글자를 읽기 어려운 사람: 저시력·노안 사용자, 화면 밝기를 낮춘 휴대폰 사용자, 밝은 야외에서 보는 사용자.

## 3. 원칙

1. **기준은 WCAG 2.2 AA.** 글자 4.5:1. 큰 글자(24px 이상, 또는 18.66px 이상이면서 굵기 700 이상)는 3:1. 링크 밑줄 같은 비텍스트(non-text)는 3:1.
2. **Tailwind 기본 팔레트 안에서 해결한다.** 새 색 토큰은 만들지 않는다(Q1 결정).
3. **위계를 유지한다.** 주 글자(neutral-100~300) > 보조 글자(neutral-400) > 링크 밑줄(neutral-500).
4. **색만 바꾼다.** 글자 크기·굵기·배치·애니메이션·문구는 그대로 둔다.
5. **새 라이브러리 없음.** e2e의 색 변환도 브라우저 canvas로 한다. 브레이크포인트 규칙(`md` 768·`lg` 1080·`xl` 1440만, `sm:`·`2xl:` 금지, `tests/test_m5_breakpoints.py`)은 그대로다. 이번 범위에는 반응형 변경이 없다.
6. **기존 테스트는 바꾸지 않는다.** 이 색 클래스에 의존하는 기존 테스트는 없다(`tests/test_m*.py`, `frontend/e2e/*.spec.ts`, `node --test` 대상 grep 0건).
7. 시안(`docs/design/`)이 없으므로 이 문서 5·6절의 색 표가 시안을 대신한다.

### 확인한 사실 중 기획에 영향 주는 것

- M7 리뷰에서 12px 보조 글자 `text-neutral-500`이 약 3.8~4.2:1, 링크 밑줄 `decoration-neutral-700`이 약 1.9:1이라는 지적이 나왔다. 화면 전체의 관행이라 M7 범위에서 빼고 이번에 다룬다.
- `text-neutral-500`은 이 사이트의 어떤 배경에서도 최대 4.23:1이라 4.5:1에 못 미친다. 팔레트에서 4.5:1을 넘는 가장 어두운 단계가 400이다(5-2 표).
- `opacity-*`는 비활성 컨트롤(`disabled:`·`aria-disabled:`)과 오버레이 스크롤바 thumb(`aria-hidden`, 글자 없음)에만 있다. 글자 색에 알파를 쓴 곳(`text-white/50` 같은)도 없다. 그래서 e2e는 조상 `opacity`를 계산하지 않아도 된다.
- 지도(`WorldMap.tsx`)와 추이 차트(`RiskChart.tsx`)의 SVG는 `role="img"`이고 `aria-hidden`이 아니다. SVG 글자도 e2e 측정 대상이다.
- 대상 목록은 neutral 계열 색 클래스 grep으로 만들었다. 색 글자(red-400 6.3~6.9, rose·sky·amber-300 등)는 표본 계산으로 통과를 확인했다(전수 측정은 아님, 1-1 "확인 못 한 것").

## 5. 대비 기준과 계산

### 5-1. 계산 방법

- 색 값: Tailwind 4.3.4 `node_modules/tailwindcss/theme.css`의 oklch를 sRGB 8비트로 바꾼 값.

  | neutral | 300 | 400 | 500 | 600 | 700 | 900 | 950 |
  |---|---|---|---|---|---|---|---|
  | hex | `#d4d4d4` | `#a1a1a1` | `#737373` | `#525252` | `#404040` | `#171717` | `#0a0a0a` |

- 반투명 배경은 아래 색 위에 알파 합성(alpha compositing)한 색으로 계산했다. 페이지 `#07090d`, 카드 white/3%, 카드 안 카드 +2%, 쌍 탭 선택 +8%, 목록 선택 +10%.
- 공식: WCAG 2.2 상대 휘도(relative luminance)와 대비 비율 `(L1 + 0.05) / (L2 + 0.05)`. 소수 둘째 자리 반올림.

읽는 법:
- **지금 색**: 보조 글자 500·600, 링크 밑줄 700, 지도 나라 이름 `#6b7280`. **바꿀 색**: 보조 글자 400, 범례 강조 `<b>` 300, 링크 밑줄 500, 지도 나라 이름 `#9ca3af`.
- 글자: 500 열은 모든 배경에서 4.5 미만(최대 4.23), 600 열은 2.57 이하다. 400 열은 모두 4.5 이상이다(최저 4.90, 이미 400인 이유 칩). 바꾼 뒤 대상 글자의 최저값은 6.55(선택된 쌍 탭 위 "실시간 24시간 N")다.
- 밑줄: 700 열은 모두 3 미만(최대 1.93)이고, 500 열은 모두 3 이상(최저 3.10)이다. 600 열은 모두 3 미만이라 밑줄 후보가 아니다. 실제 밑줄 위치에서 500은 3.85~4.20이다.
- 지도 나라 이름: `#9ca3af`는 모든 배경에서 4.5 이상이다.

## 7. 검증 방법과 한계

- **소스 계약**(pytest, `tests/test_m8_contrast.py`): 주석을 뺀 `frontend/src`·`frontend/app` 소스에서 어두운 회색 글자·채움 클래스, 옛 지도 회색, 어두운 밑줄 클래스를 0건으로 지킨다. 패턴은 이슈 1-1·1-2 "테스트".
- **화면 실측**(e2e, `frontend/e2e/contrast.spec.ts`): Firefox·WebKit에서 폭 4개 × 상태 6개(기본 홈, 가이드 모달 열림, "주목 국가 기준" 펼침, 체크리스트 항목 하나 체크, 국가 쌍 탭 선택, 대피소 결과)의 보이는 글자 전부와 밑줄을 잰다. 동작 줄이기(`reducedMotion: "reduce"`)를 켜 애니메이션이 끝난 상태에서 잰다.
- **수동**: 지도 hover 툴팁은 SVG hover가 e2e에서 불안정해 앱 브라우저에서 확인한다.
- **한계**(문서로 남기고 받아들임)
  - `background-image`(그라데이션)는 계산하지 않는다. `body`의 파란 빛은 최대 8%이고 400 기준 6.6:1 이상이라 결론이 바뀌지 않는다.
  - 조상 `opacity`는 계산하지 않는다(4절: 비활성 컨트롤과 thumb에만 있음).
  - 가상 요소(`::before`·`::after`) 글자, `input`·`select`의 값과 placeholder, `option`은 재지 않는다. placeholder는 소스 계약 패턴으로만 지킨다.
  - SVG 글자는 viewBox 배율 때문에 실제 크기가 계산된 `font-size`와 다를 수 있어 크기와 관계없이 4.5:1로 본다.
  - "불러오는 중…"처럼 로드 중에만 보이는 글자는 측정 시점에 없을 수 있다. 소스 계약이 막는다.

## 8. 사용자 흐름 (바뀌는 부분만)

1. 휴대폰으로 접속 → 헤더의 "15분 갱신 · N분 전", 요약의 기준일·"실시간 24시간", 여행경보 줄, 지도 범례·조작 안내를 화면 밝기를 낮춘 상태에서도 읽는다.

| 항목 | 이유 |
|---|---|
| 비활성 컨트롤의 `disabled:opacity-*`·`aria-disabled:opacity-*`(SegmentedControl, 대피소 버튼, 쪽 이동) | 비활성 UI 구성 요소는 WCAG 1.4.3 예외 |
| StatusText `animate-pulse` 깜빡임 중 순간 대비 하락 | 애니메이션 변경은 범위 밖. 동작 줄이기 설정에서는 깜빡이지 않는다 |
| 장식: `border-white/*`, `divide-white/5`, 차트 격자선, 지도 경위선 | 정보·조작에 필요한 시각 정보가 아니라 1.4.11 대상이 아니다 |

| 대피소 검색창 placeholder | 이미 통과(6.94, M7) |
| 후속 후보: 입력창·select 경계 `border-white/15` | 비텍스트 3:1에 못 미칠 수 있으나 측정하지 않았다(확실하지 않음). 따로 측정 필요(Q4) |
| 후속 후보: 포커스 표시(outline) 대비 | 측정하지 않음(확실하지 않음) |

| 글자 크기·굵기 변경, 라이트 모드, 색 체계 전체 개편, APCA 등 WCAG 3 초안 기준 | 이번 목표(AA 미달 해소) 밖 |
| GitHub 이슈·마일스톤·라벨 생성 | 사용자 컨펌 후 메인 세션 담당 |

## 11. 결정 사항 (열린 질문 Q1~Q4, 2026-11-11 사용자 결정: 네 질문 모두 추천안 채택)

|---|---|---|---|---|
| Q1 | 500과 600이 모두 400이 되면 가장 흐린 "힌트"(600) 단계가 따로 남지 않는다. 어떻게 할까 | 400 하나로 모은다. 팔레트만 쓰고 10/11/12px 글자 크기와 굵기로 위계를 둔다 | `globals.css` `@theme`에 중간 단계(예: oklch 64%, 약 6.2:1)를 새로 정의해 600이던 6곳에만 쓴다 | 1-1 |
