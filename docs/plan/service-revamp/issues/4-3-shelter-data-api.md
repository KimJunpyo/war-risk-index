# 민방위 대피시설 데이터 수집과 조회 API

## 배경

권고 문장에 "가까운 대피소 위치 알아두기"가 있지만 화면에서 찾을 방법이 없다. 행정안전부 민방위 대피시설 공공데이터를 받아 좌표 기준으로 가까운 대피소를 돌려주는 API를 만든다. 화면은 4-4에서 만든다.

## 범위

- 포함: 대피시설 데이터 수집 스크립트(주기 갱신), 조회 API
- 제외: 화면(4-4), 해외 대피소, 지진·해일 등 다른 재난 대피소(제공처가 같아도 이번엔 민방위만)

## 할 일

1. **데이터 확인(첫 할 일)**: 공공데이터포털에서 민방위 대피시설 데이터의 정확한 이름, 제공 형태(API인지 파일인지, 다른 포털로 연결되는지), 응답 필드(시설명, 주소, 좌표계, 수용 인원, 시설 구분), 전체 건수, 갱신 주기, 호출 한도, 라이선스를 확인해 PR 설명에 적는다. 확인하지 못한 사실은 단정하지 않는다(plan.md Q13, Q14).
2. 루트에 수집 스크립트(예: `shelters.py`)를 만든다. 결과는 `data/shelters.csv`(git 제외, E 드라이브)에 저장하고, 좌표는 WGS84 위경도로 변환해 둔다. 기존 스크립트처럼 파일 mtime으로 갱신 주기를 지킨다(주기는 1에서 확인한 원천 갱신 주기에 맞춤).
3. `backend/app/main.py`의 `_daily_refresh` 흐름에 갱신을 붙이되, 실패해도 다른 갱신을 막지 않게 `try/except` + `log.exception`으로 감싼다(여행경보와 같은 방식).
4. `GET /api/shelters?lat=..&lon=..` 를 추가한다.
   - `lat`·`lon`은 소수점 2자리까지만 받는다(그 이상이면 422). 대한민국 범위(위도 33~39, 경도 124~132) 밖이면 빈 목록.
   - 반경 5km 안에서 가까운 순 최대 10곳: `name, address, lat, lon, distance_m, capacity, kind`.
   - 데이터 파일이 없으면(키 없음 포함) 빈 목록과 `available: false`.
5. 시·군·구 선택용 `GET /api/shelters/regions`(시·도 → 시·군·구 목록)와 `GET /api/shelters?region=..`(해당 지역 전체, 최대 50곳)를 추가한다. 위치 권한 거부 사용자의 대체 경로다.
6. 거리 계산 함수에 `self_check()`(서울시청↔광화문 등 알려진 두 점 거리 오차 1% 이내)를 둔다.
