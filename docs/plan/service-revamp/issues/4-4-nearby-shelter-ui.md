# 내 주변 대피소 화면

## 배경

4-3의 대피소 API를 화면에 붙인다. 위치 정보는 민감한 개인정보이므로 사용자가 버튼을 눌렀을 때만 요청하고, 거부해도 지역 선택으로 같은 정보를 얻을 수 있게 한다. 서버에는 약 1km 단위로 반올림한 좌표만 보낸다.

## 범위

- 포함: "내 주변 대피소" 영역(위젯 신규), 위치 요청, 지역 선택 대체 경로, 외부 지도 링크
- 제외: 지도 SDK 삽입, 길찾기, 위치 저장·자동 재조회, 해외 대피소(plan.md Q15)

## 동작 정의

- 처음에는 버튼 "내 주변 대피소 찾기"와 "지역으로 찾기"만 보인다. 페이지 로드 시 `navigator.geolocation`을 호출하지 않는다.
- 버튼 클릭 → `getCurrentPosition` → 위경도를 소수점 2자리로 반올림 → `GET /api/shelters?lat&lon`.
- 위치 거부·실패·시간 초과(10초) → "위치를 쓸 수 없습니다. 지역으로 찾아 주세요." 안내와 함께 지역 선택을 연다.
- 결과: 대피소 이름, 주소, 거리(반올림 좌표 기준이므로 "약 N m"), 수용 인원(있으면), "지도에서 보기" 외부 링크(새 탭).
- 결과 0건(반경 밖·해외) → 영역 안에 "주변 5km 안에 등록된 대피소가 없습니다" 대신 지역 선택을 안내한다. API `available: false`면 영역 전체를 숨긴다.
- 화면 아래에 고지 문구: "위치는 대피소 검색에만 쓰고 저장하지 않습니다. 약 1km 단위로 반올림해 보냅니다." 와 데이터 출처·기준일.
- 배치: 비상 대비 체크리스트 근처(plan.md Q1).

## 할 일

1. `frontend/src/entities/shelter/`(타입·조회 훅), `frontend/src/widgets/nearby-shelters/`(위젯)를 만든다.
2. 위치 반올림을 한 함수로 두고 요청 URL 생성에서만 사용한다.
3. 외부 지도 링크 형식(어느 지도 서비스의 공개 URL을 쓸지)과 그 서비스의 링크 이용 조건을 확인해 PR에 적는다.
4. `HomePage.tsx`에 배치하고 footer 데이터 출처에 행정안전부 민방위 대피시설을 추가한다.

## 인수 조건

- [ ] 홈 화면 로드 후 버튼을 누르기 전까지 브라우저 위치 권한 팝업이 뜨지 않는다(시크릿 창에서 확인).
- [ ] 위치 허용 시 개발자 도구 Network의 `/api/shelters` 요청 URL에서 `lat`·`lon`이 소수점 2자리 이하다.
- [ ] 위치 허용 시 결과가 거리 오름차순으로 표시되고 각 항목에 이름·주소·거리가 있다.
- [ ] 위치 거부 시 안내 문구와 지역 선택이 표시되고, 시·도 → 시·군·구를 고르면 해당 지역 대피소 목록이 표시된다.
- [ ] 위치 요청 후 `localStorage`, `sessionStorage`, 쿠키에 좌표가 저장되지 않는다(개발자 도구 Application 탭 확인).
- [ ] 고지 문구와 데이터 출처·기준일이 영역 안에 표시된다.
- [ ] "지도에서 보기" 링크가 `target="_blank" rel="noreferrer"`로 열린다.
- [ ] API가 `available: false`를 반환하면 영역이 DOM에 없다.
- [ ] 버튼·지역 선택이 키보드(Tab, Enter)로 조작된다.
- [ ] `frontend`에서 `npx tsc --noEmit`, `npm run lint` 오류 0건이다.
- [ ] 브라우저(`http://localhost:3000`)에서 위치 허용·거부 두 경우를 확인했고(위치는 개발자 도구 Sensors로 서울 좌표 지정 가능) 콘솔 오류 0건이다.
