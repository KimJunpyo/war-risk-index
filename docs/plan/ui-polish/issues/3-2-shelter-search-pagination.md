# 대피소 결과 키워드 검색·페이지네이션·카드 배치

## 배경

3-1로 지역·주변의 대피소 전체를 받게 되면 결과가 수백 곳이 된다(창원시 527곳, 서울시청 5km 476곳). 지금 위젯(`widgets/nearby-shelters/ui/NearbyShelters.tsx`)은 결과를 한 목록에 모두 그리고 검색이 없다. 결과 안 키워드 검색, 페이지 나누기, 결과 카드 배치를 추가한다. 사용자 요청 "전반적으로 보기 좋게"는 아래 "결과 카드" 정의와 폭별 배치로 바꿔 검증한다.

## 범위

- 포함: 결과 영역(검색창, 결과 건수, 카드 목록, 페이지 이동), 결과 카드 구성, 대피소 위젯 안쪽 반응형
- 제외: 위치 요청·지역 선택 흐름(현행 유지), 대피소 바깥 배치(2-2), 서버 측 검색(plan.md Q4), 지도 SDK

## 동작 정의

- 검색창: 결과가 1곳 이상일 때만 보인다. 라벨 "결과에서 찾기", placeholder 예 "학교, 주민센터, 동 이름". 입력값 앞뒤 공백을 지우고, 대소문자 구분 없이 이름 또는 주소에 포함되면 남긴다. 여러 단어(공백 구분)는 모두 포함(AND).
- 입력이 바뀌면 1쪽으로 돌아간다. 새 조회(위치·지역 변경)를 하면 검색어를 비우고 1쪽으로 돌아간다.
- 결과 건수 문구: "총 N곳"(검색 없을 때), "총 N곳 중 M곳"(검색 중). 3-1의 `total`이 `items` 길이보다 크면(안전 상한에 걸림) "상위 L곳만 표시" 안내를 덧붙인다.
- 페이지당 10곳(plan.md Q7 확정, 상수 `PAGE_SIZE`). 페이지 이동: "이전" / "다음" 버튼과 "3 / 53" 형식 현재 위치. 첫 쪽에서 "이전", 마지막 쪽에서 "다음"은 `disabled`. 결과가 10곳 이하이면 페이지 이동을 숨긴다.
- 페이지를 바꾸면 결과 목록 맨 위로 스크롤하고 결과 건수 문구에 포커스를 옮기지 않는다(스크린리더는 `aria-live="polite"`로 "3 / 53쪽" 안내).
- 검색 결과 0곳: "‘검색어’가 들어간 대피소가 없습니다." 표시, 페이지 이동 숨김.
- 결과 카드: 이름(굵게, 14px), 위치 조회면 거리 배지 "약 1,234 m"(오른쪽 위), 주소(12px), 수용 인원(있을 때만 "수용 1,234명"), "지도에서 보기" 링크(새 탭). `kind`는 대부분 "공공용시설"이라 "공공용시설"이 아닐 때만 작은 배지로 표시.
- 폭별 카드 열 수: 360 1열, 768 2열(대피소가 전체 폭일 때), 1080·1440 1열(체크리스트 옆 반 폭일 때, 2-2 배치). 열 수는 위젯 폭 기준(컨테이너 쿼리)이 자연스러우면 그 방법을 쓰고 PR에 적는다.

## 할 일

1. 순수 함수를 `widgets/nearby-shelters/model/`에 둔다: `filterShelters(items, query)`, `paginate(items, page, pageSize)`(범위 밖 page는 첫·마지막 쪽으로 보정), 결과 건수 문구 생성. 별칭(`@/`) 없이 import 되게 한다.
2. `node --test`용 테스트 `widgets/nearby-shelters/model/*.test.ts`를 추가한다: 빈 검색어, 공백만, 대소문자, 여러 단어 AND, 주소만 일치, 0건, 페이지 경계(1쪽·마지막 쪽·범위 밖), 10곳 이하.
3. `NearbyShelters.tsx`에 검색창·건수·카드·페이지 이동을 붙인다. 기존 고정 문구(`FIND_NEARBY`, `FIND_BY_REGION`, `LOCATION_FAILED`, `PRIVACY_NOTICE`)와 저장소 미사용(`localStorage`·`sessionStorage`·쿠키)은 그대로. 검색어도 브라우저 저장소에 저장하지 않는다.
4. 결과 목록이 내부 스크롤 영역이 되면 1-2의 공용 오버레이 스크롤바 컴포넌트를 쓴다. 이 이슈는 내부 스크롤 없이 페이지 단위로만 보여 준다.
