# 전쟁 가능성 지수 UI 개선 기획안

작성일: 2026-11-10 · 상태: 초안 · 열린 질문 Q1~Q12 사용자 결정 반영(2026-11-10) · 이전 기획: `docs/plan/service-revamp/` (M1~M4 완료)

## 1. 목표

일반인이 휴대폰(360px)부터 큰 모니터(1440px)까지 어느 화면에서든 같은 정보를 잘리거나 겹치지 않게 보게 한다.

1. 가이드 모달 "여행경보 4단계" 표에서 단계 이름이 줄바꿈되지 않게 한다.
2. 360 / 768 / 1080 / 1440 네 폭에 맞춘 배치를 정의하고 홈 전체에 적용한다.
3. 스크롤바를 트랙 없이 thumb만 보이게 하고, 모든 OS에서 레이아웃 공간 0(옆으로 밀리지 않음)으로 만든다.
4. 내 주변 대피소 결과에 키워드 검색·페이지네이션을 붙이고 결과 카드 배치를 정리한다.
5. 푸터를 일반적인 웹 푸터 형태로 바꾸고 개인 작업물 고지, 실제 사용하는 데이터 출처, 만든 사람 링크를 넣는다.

## 2. 대상 사용자

- 일반인(통계 용어를 모른다고 가정). 주로 휴대폰으로 뉴스를 보다 들어오는 사람과 PC로 자세히 보는 사람.
- 기준 화면 폭: 360px(소형 안드로이드), 768px(태블릿 세로), 1080px(작은 노트북·태블릿 가로), 1440px(데스크톱).

## 3. 원칙

1. **가로 스크롤 0.** 네 폭 모두에서 `document.documentElement.scrollWidth <= window.innerWidth`. 가로로 넘치는 내용은 줄바꿈·배치 변경으로 해결한다(표 가로 스크롤로 숨기지 않는다).
2. **브레이크포인트는 4개 폭만.** Tailwind 기본값(sm 640, lg 1024, xl 1280, 2xl 1536)을 쓰지 않고 4절의 값만 쓴다. 숫자는 `globals.css`의 `@theme`에만 둔다(매직 넘버 금지).
3. **새 라이브러리 없음.** 이번 범위는 브라우저 기본 기능과 직접 구현만 쓴다(스크롤바 포함, Q3 결정).
4. **기존 동작 유지.** 위치 개인정보 원칙(버튼 클릭 시에만 요청, 소수 2자리 반올림, 저장 안 함), 데이터 없으면 영역 숨김 원칙은 그대로 둔다.
5. 시안(`docs/design/`)이 없으므로 이 문서 5절 배치표가 시안을 대신한다. 색·글꼴·패널 스타일은 기존 `Panel`과 어두운 테마를 따른다.

## 5. 반응형 기준

### 5-1. 브레이크포인트 (1-1에서 정의)

Tailwind v4 `@theme`에서 기본 브레이크포인트를 지우고 아래만 둔다. 이름은 익숙한 `md`·`lg`·`xl`을 재정의한다(대안은 Q1).

| 이름 | 최소 폭 | 값 | 대상 |
|---|---|---|---|
| (접두사 없음) | 0 | – | 360 기준(360~767) |
| `md` | 768px | `48rem` | 768 기준(768~1079) |
| `lg` | 1080px | `67.5rem` | 1080 기준(1080~1439) |
| `xl` | 1440px | `90rem` | 1440 기준(1440~) |

- 360px 미만(예: 320px)은 별도 디자인 없이 360 배치를 그대로 쓴다. 가로 스크롤 0만 보장한다(Q2).
- 기존 `sm:`(640)는 `md:`로 옮기고, 기존 `lg:`(1024)는 값만 1080으로 바뀐다. 이로 인해 640~767px에서 2열이던 곳이 1열이 되고, 1024~1079px에서 2열이던 곳이 1열이 된다(의도된 변경).

### 5-2. 영역별 배치표

"n열"은 그 영역 안의 열 수. 높이·폭 숫자는 컴포넌트 상수 또는 Tailwind 클래스 값으로 둔다.

| 영역 | 360 (기본) | 768 (`md`) | 1080 (`lg`) | 1440 (`xl`) |
|---|---|---|---|---|
| 페이지 컨테이너 | 좌우 여백 16px, 위아래 24px | 좌우 24px, 위아래 32px | 좌우 32px | 콘텐츠 최대 폭 1280px 가운데 정렬, 좌우 32px |
| 헤더 | 1줄: 제목(20px) + LiveBadge + 오른쪽 끝 버튼 "가이드". 설명 문단은 아래 | 제목 24px, 버튼 문구 "가이드 · 여행경보 단계" | 768과 같음 | 768과 같음 |
| 지도 + 주목 국가 | 패널 제목 줄 아래에 지도 색 기준 토글. 지도 전체 폭, 그 아래 주목 국가 1열 목록(최대 높이 320px, 내부 스크롤) | 제목과 토글 같은 줄. 지도 전체 폭, 아래 주목 국가 2열 목록(최대 높이 320px) | 지도 + 오른쪽 주목 국가 260px, 목록 최대 높이 = 지도 높이 | 지도 + 오른쪽 주목 국가 300px |
| 이번 주 변화 | 오른 나라 → 내린 나라 세로 | 2열 | 2열 | 2열 |
| 국가 쌍 탭 | 2열 카드. 카드 안 보조 문구(실시간 점수)는 큰 점수 아래 줄 | 3열 | 4열 | 4열 |
| 요약(대상 이름·상태·점수) | 이름+배지 1줄, 그 아래 종합·실시간 점수 나란히, 점수 구성 문장 전체 폭 | 이름 블록 왼쪽, 점수 오른쪽 같은 줄 | 768과 같음 | 768과 같음 |
| 여행경보 줄 | 기관마다 한 줄(외교부 → 미 → 영 순서 목록) | 한 문단으로 이어 쓰기(현행) | 768과 같음 | 768과 같음 |
| 비상 대비 체크리스트 | 항목 1열 | 항목 2열 | 대피소·재외공관 중 하나가 같이 있으면 그 영역과 1:1 2열로 나란히(체크리스트 항목은 1열), 없으면 전체 폭·항목 2열 | 1080과 같음 |

| 재외공관 연락처 | 전체 폭, 공관 1열 | 전체 폭, 공관 2열 | 체크리스트 옆 반 폭, 공관 1열 | 1080과 같음 |

| 과거 위기 사례 | 1열, 전체 폭 | 같음 | 그리드 두 열 전체 폭 | 같음 |
| FAQ | 1열, 전체 폭 | 같음 | 같음 | 같음 |
| 푸터 | 블록 세로 쌓기: 소개·고지 → 데이터 출처(1열) → 만든 사람 → 하단 바 | 2열: 왼쪽 소개·만든 사람, 오른쪽 데이터 출처(1열). 하단 바 전체 폭 | 3열: 소개·고지 / 데이터 출처(2열 목록) / 만든 사람. 하단 바 전체 폭 | 1080과 같음 |

참고: 현재 1024px 이상에서 위협 사건 패널이 `lg:col-span-2`라 뉴스 패널(`lg:row-span-2`) 옆 두 번째 행 왼쪽 칸이 비고, 그만큼 빈 공간이 생길 수 있다(정적 분석, 브라우저 확인 못 함 → 2-2에서 확인). 위 표의 1080 배치가 이를 해소한다.

## 6. 스크롤바 방식 비교 (사실 확인 결과)

요구: 트랙 없이 thumb만 보이고, 스크롤바가 생겨도 레이아웃 공간 0(옆으로 밀리지 않음). 대상: 페이지 전체, 주목 국가 목록, 뉴스 목록, 가이드 모달.

### 확인한 사실

| 기능 | 내용 | 지원 | 출처 |
|---|---|---|---|
| `scrollbar-width: thin \| none` | 두께 지정. `none`은 숨김(스크롤은 유지) | Chrome·Edge 121, Firefox 64, Safari 18.2 (Baseline 2024) | web.dev 2024-12, WebKit Safari 18.2 릴리스 노트 |
| `scrollbar-color: <thumb> <track>` | 색 지정. track에 `transparent` 가능 | Chrome·Edge 121, Firefox 64, Safari·iOS Safari 26.2 (Baseline 2025-12) | web-platform-dx features explorer |
| `scrollbar-gutter: stable` | 클래식 스크롤바일 때 스크롤이 없어도 자리를 미리 비워 둬 밀림을 막는다. **자리를 차지한다(공간 0 아님).** 오버레이 스크롤바에는 효과 없음 | Baseline 2024 | MDN `scrollbar-gutter` |
| `::-webkit-scrollbar` | 비표준. `scrollbar-color`·`scrollbar-width`가 `auto`가 아니면 이 스타일은 무시된다. 이 의사 요소에 width를 주면 오버레이가 아닌 클래식 스크롤바(자리 차지)가 된다 | Chromium·Safari. Firefox 미지원(MDN 본문에는 명시 없음, 확실하지 않음) | MDN `::-webkit-scrollbar`, Chrome for Developers "Scrollbar styling" |
| `overflow: overlay` | 예전 비표준 값. 지금은 `auto`의 별칭이라 콘텐츠 위에 겹쳐 그리지 않는다 | – | MDN `overflow` |
| 클래식 vs 오버레이 | 클래식은 항상 거터를 차지, 오버레이는 콘텐츠 위에 그려져 공간 0 | – | MDN `scrollbar-gutter`, Chrome for Developers |

|---|---|---|---|

| iOS·Android 브라우저 | 오버레이 | 가능(기본 상태) | |
| Windows Chrome·Edge | 클래식 | **불가** | Windows 11용 오버레이(Fluent) 스크롤바가 기본 켜짐인지는 확실하지 않음 |
| Windows Firefox | Windows 11 "항상 스크롤 막대 표시" 설정을 따라 오버레이일 수 있음 | 설정에 따라 다름 | 확실하지 않음 |

### 방식 비교

| 방식 | 내용 | thumb만 보임 | 공간 0 (Windows Chrome·Edge) | 밀림 없음 | 새 의존성 |
|---|---|---|---|---|---|
| A. 표준 CSS | `scrollbar-width: thin` + `scrollbar-color: <thumb> transparent`, 내부 스크롤 영역에 `scrollbar-gutter: stable` | 예(트랙 투명) | 아니오(얇은 거터가 남음, 폭 px는 브라우저별로 다름·확실하지 않음) | 예(gutter로 미리 확보) | 없음 |
| B. 자체 구현 | 기본 스크롤바 `scrollbar-width: none` + 절대 위치 thumb를 스크롤·ResizeObserver로 갱신, 드래그 처리 | 예 | 예 | 예 | 없음(코드 약 100줄 이상 추정, 확실하지 않음) |
| C. OverlayScrollbars | 기본 스크롤바를 숨기고 겹쳐 그리는 스크롤바. 기본 스크롤 동작 유지 | 예 | 예 | 예 | 있음. MIT 라이선스(GitHub 확인). React 래퍼 패키지 이름·번들 크기는 확인 못 함(확실하지 않음) |

**결정 (Q3, 2026-11-10)**: **B. 직접 구현**을 채택한다(1-2). 네이티브 스크롤바를 `scrollbar-width: none` + `::-webkit-scrollbar { display: none }`으로 숨기고, 공용 훅·컴포넌트가 thumb만 겹쳐 그린다. 모든 OS에서 공간 0·같은 모양. thumb 크기·위치 계산은 별칭 없는 순수 함수로 분리해 `node --test`로 검증한다.

- A(표준 CSS만): Windows Chrome·Edge에서 얇은 거터가 남아 요구(공간 0)를 못 맞춰 **비채택**.
- C(OverlayScrollbars): 기능은 맞지만 새 의존성이고, 필요한 기능(위치 반영·드래그·표시 시점)이 작아 직접 구현으로 충분해 **비채택**.

## 7. 사용자 흐름 (개선 후, 바뀌는 부분만)
