## 공통 검증 (모든 이슈의 인수 조건에 포함)

- **pytest:** 프로젝트 루트에서 `.venv\Scripts\python.exe -m pytest tests`가 전부 통과한다. 새 파일도 아래 두 테스트에 걸리지 않아야 한다.
  - `test_no_key_like_strings_in_repo`: 영숫자가 32자 이상 이어진 문자열 금지
  - `test_no_threat_references_in_repo`
- **프론트 검사(프론트 파일을 바꾼 이슈만):** `frontend`에서 `npx tsc --noEmit`, `npm run lint` 오류 0건. 루트에서 `node --test frontend/src/**/*.test.ts` 통과.
- **인수 조건 표시:** 각 인수 조건 끝에 확인 방법을 붙인다.
  - `[테스트]`: pytest 등 자동 테스트
  - `[명령]`: 명령을 실행해 결과로 확인한다. PR 본문에 명령과 결과 요약을 적는다.
  - `[수동]`: 문서화된 절차로 사람이 확인한다. PR 본문에 확인일과 결과를 적는다.
- **로컬과 서버 구분:**
  - M1·M2는 로컬(Windows 11, PowerShell)에서 모두 확인할 수 있다.
  - 서버가 있어야 하는 확인은 각 이슈의 "서버에서 확인(M3)"에 적어 두고 3-1·3-2에서 체크한다.
- **데이터 쓰기 명령:** 지수 재계산, 수집, 이전용 압축은 로컬 백엔드 갱신 스레드를 멈춘 상태에서 실행한다. 백엔드를 멈추거나 `LIVE_UPDATES=0`으로 띄운다.
- **비밀값·해시:** 비밀값(`.env` 내용)은 저장소, PR, 이슈에 쓰지 않는다. 해시 값도 저장소 파일에는 넣지 않는다(PR 본문은 괜찮다).
- **기존 테스트 변경:** 기존 테스트를 바꿔야 하면 명세가 바뀐 이유를 PR 본문에 적는다. 통과시키려고 고치지 않는다.
- **임시 파일 삭제:** 임시 폴더나 임시 venv를 지울 때는 대상 목록을 먼저 보여 준다.
- **커밋:** Conventional Commits 형식으로, 이슈별 브랜치에서 한다(`main`에 직접 커밋 금지).

## M1. 무인 운영을 위한 코드 보강 (로컬 확인)

코드에서 세 가지 문제를 막는다: 갱신 스레드가 파일을 다시 쓰다 잘린 파일이 생기는 문제, 갱신이 멈추는 문제, 오래된 데이터를 그대로 보여 주는 문제. 그리고 서버에 설치·빌드할 수 있는 상태인지 로컬에서 확인한다. 이 마일스톤만 끝나도 로컬 기능은 그대로 돈다. 바뀐 쓰기 방식, 타임아웃, 헬스 체크는 테스트로 확인할 수 있다.

**완료 조건**
- **원자적 쓰기:** `build_index.py`, `build_country_index.py`, `blend.py`, `ucdp.py`의 쓰기 7곳이 임시 파일→교체 방식이다.
  - 쓰는 도중 실패해도 기존 파일이 그대로 남는다는 테스트가 통과한다.
  - 바꾸기 전과 후의 지수 결과 파일 4개의 SHA-256이 같다.
- **다운로드 타임아웃:** 저장소 Python 코드에 `urlretrieve`가 0건이다. 응답을 보내지 않는 서버에 대해 다운로드가 타임아웃 예외로 끝나는 테스트가 통과한다.
- **헬스 체크:** `GET /api/health`가 데이터가 신선하면 200, 오래됐거나 파일이 없으면 503을 준다(테스트). 로컬 백엔드에서는 200이다.
- **의존성:** `backend/requirements.txt`가 런타임 의존성만 담고 모두 `==`로 고정한다.
  - 이것만 설치한 새 venv에서 백엔드 주요 엔드포인트가 200이다.
  - `import backend.app.main`이 matplotlib을 불러오지 않는다.
- **프로덕션 빌드:** `next build`가 성공한다. `next start`와 백엔드로 홈 화면과 메타데이터 경로(`robots.txt`, `sitemap.xml`, manifest, 아이콘, OG 이미지)가 동작한다. 메모리와 빌드 시간 측정값이 기록돼 있다.
- 공통 검증을 통과한다.

**이슈**
- 1-1 지수·UCDP·가중치 파일 원자적 쓰기(임시 파일→교체) (`issues/1-1-atomic-writes.md`)
- 1-2 GDELT·UCDP 다운로드 타임아웃 (`issues/1-2-download-timeout.md`)
- 1-3 데이터 신선도 헬스 체크 `/api/health` (`issues/1-3-health-endpoint.md`)
- 1-4 Python 런타임 의존성 고정과 백테스트·테스트 의존성 분리 (`issues/1-4-python-requirements.md`)
- 1-5 프로덕션 빌드·실행 확인과 메모리 측정 (`issues/1-5-production-build.md`)

## M2. 배포 설정과 운영 런북 (로컬 확인)

서버에서 쓸 설정 파일과 런북을 만든다. 서버 없이 확인할 수 있는 부분은 로컬에서 실제로 돌려 본다: 정적 검사, 저장소 밖 새 사본에서의 설치·빌드, 이전용 압축·풀기·mtime 비교, 백업 스크립트.

**완료 조건**
- **설정 파일:** `deploy/`에 다섯 가지 파일이 있다: Caddy 설정, systemd 서비스 파일 2개, 프론트 빌드 환경변수 예시, 백업 스크립트. 정적 검사 테스트가 통과하고 모두 LF로 커밋돼 있다.
- **`.env.example`:** `CORS_ORIGINS`·`LIVE_UPDATES` 설명이 주석으로 들어 있다. 기존 `.env.example` 테스트는 고치지 않은 채 통과한다.
- **런북 구성:** 다음 절이 있다: 개요(서버 규약·서버 사양), 서버 준비, 첫 배포, 업데이트, 되돌리기, 데이터 이전, 백업·복원, 가동 감시. 모든 명령 블록에 실행 위치(로컬 PowerShell / 서버 bash)가 표시돼 있다.
- **로컬 리허설:** 저장소 밖에 새로 clone한 사본에서 런북 순서대로 한 venv 설치, `npm ci`, `npm run build`가 성공한다. 이전용 압축을 풀어 띄운 백엔드가 원본과 같은 데이터를 준다.
- **서버 전용 표시:** 서버에서만 실행할 수 있는 명령에는 "M3에서 확인" 표시가 있다.

**이슈**
- 2-1 배포 설정 파일: Caddy·systemd·환경변수 예시 (`issues/2-1-deploy-config.md`)
- 2-2 운영 런북 1: 서버 준비·첫 배포·업데이트·되돌리기 (`issues/2-2-runbook-deploy.md`)
- 2-3 운영 런북 2: 데이터 이전·백업·복원·가동 감시와 백업 스크립트 (`issues/2-3-runbook-data-backup.md`)

## M3. 서버 첫 배포와 운영 리허설 (서버 필요)

`plan.md` 9절 사용자 행동(U1~U4, U7)이 끝나면 런북대로 실제 서버에 배포한다. 그리고 백업·복원·가동 감시·되돌리기를 한 번씩 해 본다. 런북과 다르게 동작한 곳은 같은 PR에서 런북을 고친다.

**완료 조건**
- **접속:** `https://<도메인>/`가 유효한 인증서로 200을 주고, `http://`는 HTTPS로 리디렉션된다. 8000·3000 포트는 밖에서 접속되지 않는다.
- **안정성:** `/api/health`가 200이고, 다음 날 일별 재계산 뒤에도 200이다. 서버를 재부팅하면 세 서비스가 자동으로 시작된다.
- **화면과 로그:** 브라우저에서 홈 화면이 동작한다(콘솔 오류 0건, CORS 오류 0건). 서버 로그 어디에도 좌표 쿼리(`lat=`)가 없다.
- **리허설:** 네 가지를 마쳤다.
  - 매일 백업이 생긴다.
  - 복원 리허설 뒤 API가 정상이다.
  - 가동 감시 알림을 실제로 받았다.
  - 직전 커밋으로 되돌렸다가 다시 돌아왔다.
- **실측값:** 서버에서 잰 메모리(VmHWM), 스왑, OOM 기록이 런북에 반영돼 있다.

**이슈**
- 3-1 서버 첫 배포와 데이터 이전 (`issues/3-1-first-deploy.md`)
- 3-2 백업·복원·가동 감시·되돌리기 리허설 (`issues/3-2-ops-rehearsal.md`)
